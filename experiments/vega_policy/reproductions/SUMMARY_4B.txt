THE FIX  (0001-Fix-NaN-crash-in-no-engine-control-on-Vega-4B.patch)
--------------------------------------------------------------------------
  CRASH:  compare.py --method linear_fb --seed 1  (VEGA_SIZE=4b), step 3
          ValueError: Probabilities contain NaN   (in fit_T_feedback)
          run.sh uses set -e, so this stopped the whole run.

  CAUSE:  Bilinear.forward (the no-engine control) masks padded answer slots
          with -1e4 before the softmax. On 4B the features are 15,360-dim
          and real logits can fall below -1e4 (seen: -14,924, -16,009 on an
          8-option row). In a batch padded for longer rows, the softmax then
          puts all probability on the fake padded slots: the real options
          get exactly 0, p/p.sum() = 0/0 = NaN, crash.
          Training itself was healthy (all params < 0.15, no NaN).
          The authors only ran 0.8B, so they never hit it.

  FIX:    compare.py, one line (plus a comment):
            -  return torch.log_softmax(lg.masked_fill(~mask, -1e4), -1)
            +  return torch.log_softmax(lg.masked_fill(~mask, -1e9), -1)
          Not -inf: the entropy term multiplies exp(lp) * lp over all
          slots, and 0 * -inf = NaN.

  CHECKS: - 0.8B linear_fb seeds 0, 1, 2 rerun with the fix: metrics are
            identical to before. The fix changes nothing where the bug did
            not fire, so the 0.8B results already sent stand.
          - 4B linear_fb seed 0: identical before and after the fix.
          - 4B seed 1 (the crash) now completes: acc 0.237, in line with
            seed 0 (0.271) and seed 2 (0.220).
          - The same -1e4 mask is in bench_rl.py and vpol/vega.py, but there
            logits come from Vega's engine divided by a temperature clamped to
            [0.2, 20], so they cannot reach -1e4. Left unchanged.
